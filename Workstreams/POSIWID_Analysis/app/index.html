POSIWID · The purpose of a system is what it does

POSIWID analysis

Judge a system by what it actually does, not by what it's meant to do. Work through the five questions below. The finished analysis builds itself on the right. Copy or download it as a Markdown file, or as a prompt that hands the method and your analysis to any AI assistant.

POSIWID was described by the British cybernetician Stafford Beer in his 1979 book The Heart of Enterprise.

Everything stays in this browser. Nothing is sent anywhere. Your draft is kept on this device until you clear it.

About the system
1 What is the system doing?

Observe, don't explain. Write what actually happens, as a camera would see it, with the evidence. Leave intentions and reasons for question 2.

2 What is it expected to do?

State the expectation and where it comes from: a spec, a standard, a customer, a target. If nobody can say what it should do, stop here and define that first.

Define the expectations before you look for gaps. Without them, a gap is only an opinion. Write down what each stakeholder thinks the system is for, and agree on one statement, then come back to questions 3–5.
3 What are the gaps?

Each gap is a difference between question 1 and question 2. If a gap doesn't point back to an observation, it's a guess. Add the evidence.

4 What could close the gaps?

Prefer changes you can undo. For each change, name the gap it closes and how you'd roll it back if it doesn't work.

5 What is the measurable change?

One number that tells you whether it worked: a baseline, the current value, a target, and how anyone can check it.
